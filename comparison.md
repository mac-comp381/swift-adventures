# Comparing Languages

### Question1: How would you describe the experience and feel of reading code in Swift, and in Java? What is it like for you in each language?
I think reading Swift versus Java involves a trade-off. Swift feels more concise and flexible because I do not always have to define a class or wrap functions inside a class. There are instances where Java feels easier to follow because of its explicit structure. Overall, I enjoyed reading Swift more because it expresses the same functionality with less code. 

### Question2: Where do you find that each language draws your attention as you read? Did you notice different aspects of the code while reading in the different languages?
Swift draws my attention more to what the code is doing, while Java draws my attention to how it is done. forexample, updating dictionary values in Swift feels more direct, while Java makes the individual steps more explicit.

### Question3: Which of the differences you mentioned do you suspect are differences in your own personal familiarity with the two languages, versus differences in the languages themselves?
I have done projects in both languages, so I think the differences reflect both my familiarity and the languages themselves. Swift's concise syntax is nice, but it can sometimes make the code harder to follow. Both have their trade-offs.
## Specific Differences

### Comparison 1
Trailing closure syntax, swift places the closure outside the function's parentheses.
Anonymous closure arguments-Swift uses $0 instead of explicitly naming the parameter s, as Java does.

### Comparison 2
type aliases, swift names [Clue] as Response, while Java uses List<Clue> directly.
extensions, swift adds methods outside the original type definition, while Java defines them inside the class.

### Comparison 3
Swift updates dictionary values directly using subscripts, while Java uses put() and getOrDefault() which dictionary access syntax. 

### Comparison 4
Swift arrays have value semantics, while Java requires an explicit copy to avoid sharing the same list.
